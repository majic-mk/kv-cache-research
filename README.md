These 128 checks are software evidence, not model-quality or GPU-performance results. The first future smoke set has three development contexts, with no held-out samples used for tuning.

The main hypothesis concerns regional quantile-calibration transfer in reusable KV compression. The baseline uses masked dense caches, so retained-token ratios **do not demonstrate physical memory savings**. The proposed complex intervention has not been implemented; first establish whether simpler explanations and controls eliminate the observed problem.

## Run locally without installation

Python 3.11+ and Git are required; the runtime and test suite use only the standard
library. From this repository root:

```sh
python -m unittest discover -v
python -m kv_harness --help
python -m kv_harness cpu-fixture --output outputs/demo
python -m kv_harness validate \
  --manifest outputs/demo/manifest.json --results outputs/demo/results.jsonl
python -m kv_harness analyze \
  --manifest outputs/demo/manifest.json --results outputs/demo/results.jsonl \
  --baseline fixture_baseline --candidate fixture_candidate \
  --allow-nonexperimental --output outputs/demo/summary.json
python -m kv_harness ledger --path records/cost_ledger.csv
```

Use a new output directory for each run. Files are atomically published without
replacement. The two fixture methods perform identical hashing and CPU-copy work
on generated bytes. Their measured wall times test the plumbing, and cannot be
interpreted as an algorithm comparison. Fixture outputs are ignored by Git.

## Implemented

- Immutable, checksummed manifests: Git revision, staged/unstaged/combined diff
  hashes, untracked file hashes, immutable model/dataset pins, seed, configuration,
  Python/platform/package versions, and explicit hardware metadata
- Strict result JSONL: duplicate/unknown fields, malformed values, checksum
  mismatches, mixed evidence classes, incomplete or duplicate pairs, and missing
  timing costs are rejected
- Separate `real_model`, `cpu_fixture`, and `simulation` evidence labels. Fixture
  analysis requires an explicit opt-in and stays labeled nonexperimental
- End-to-end wall time, disjoint or overlapping phase costs, preprocessing,
  scoring, host/device copies, and measured shared-setup amortization
- Separate logical token/byte budgets from physically allocated/stored bytes and
  allocator peaks; masking is explicitly distinguishable from KV compaction
- Paired context/trace-cluster bootstrap. Questions sharing a cache use the same
  `cluster_id`; repeat measurements do not inflate the independent sample count
- Deterministic bootstrap seeds and result-content hashes in every summary
- Read-only cost-ledger audit, with decimal amounts and no currency conversion

## What remains before a real experiment

1. Finalize the research question, closest prior work, strong baselines, stop
   conditions, held-out evaluation plan, and input/output quality metrics
2. Pin the actual model, dataset, tokenizer, implementation, and configuration.
   No guessed SHA, branch, or floating revision may substitute for a verified pin
3. Write a model adapter and reproduce the author baseline without policy changes
4. Verify output equivalence where required, memory layout, CUDA synchronization,
   real setup costs, cache lifetime, and grouped evaluation leakage boundaries
5. Obtain the specific GPU rental/budget approval and record actual costs
6. Only after the baseline gate, implement the selected intervention and evaluate
   on independent contexts with paired controls

`configs/gpu_pilot.template.json` is an inert planning document with zero authorized
GPU hours/spend and unresolved source pins. It does not launch or rent a server. The separate `echo_pilot` runner requires an actual frozen GPU environment lock, staged checkpoint, clean checkout and explicit execution flag.

## Contracts and limitations

Read [the evidence contract](docs/evidence_contract.md) before writing an adapter.
Manifest checksums detect changes relative to a supplied digest; they are not
signatures and do not prove that an experiment actually ran. A human or audited
adapter can still mislabel evidence. `real_model` manifests require a clean,
committed checkout. Submodules and Git index flags that can hide modifications
are currently rejected. Dirty fixture snapshots record hashes, not restorable
archives. Avoid changing source while snapshotting or running experiments.

Published files are read-only and the API refuses to overwrite them; a filesystem
owner can still edit or remove them. Archive actual source, inputs, outputs,
runtime logs and hardware/driver details when conducting real experiments. Keep
credentials and private environment variables out of explicit manifest metadata.

No remote repository publication is implied by a local commit. This scaffold
does not choose or confirm a license for third-party research code.
